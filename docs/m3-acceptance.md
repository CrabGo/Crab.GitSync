# M3 验收记录

## 功能范围

- P14：命名列表定时 fetch，默认关闭；共用调度准入、并发上限、仓库锁、代理及网络重试。忙碌顺延，休眠不补跑积压，多个同到期列表按最近运行时间公平选择。只在失败或出现新远端提交时汇总通知。临时仓库/本地远端测试及隔离 Wails 实例一分钟定时运行、重启配置恢复和关闭开关已验证，详细证据见开发计划。
- P15：指定远端 fetch 和目录/终端/GitHub/脱敏地址快捷操作。参数直接传递，重新验证扫描范围、路径和远端；失败重试保留远端，部分 fetch 不更新完整成功时间。临时双远端和隔离界面验证指定 origin 成功且不访问失败 other。
- P16：按已跟踪文件选择撤销，默认不选择文件且不备份；可显式保存所选工作区与独立暂存内容，再从仓库菜单确认恢复。确认或选择变化会要求重新勾选。备份保存于用户配置目录 Crab.GitSync/discard-backups，不自动清理或提交。预览最多 500 个候选文件，所选原始工作区及暂存内容总计不超过 64 MiB。新增/未跟踪、未选文件和子模块内部修改保留。

## P16 安全及自动化证据

internal/gitengine/discardfiles_test.go 覆盖任意二进制、CRLF/末尾空白、工作区与暂存区不同内容、已删除目录/暂存删除、字面文件名、符号链接父目录拒绝、取消、陈旧预览/HEAD、备份写入失败、恢复前新修改、错误仓库/ID、损坏备份及重复恢复。Windows 上符号链接测试实际通过，没有跳过。

discardservice_test.go 覆盖明确确认、空选择、扫描范围、共享读取租约阻止修改、陈旧预览与备份写入失败不修改文件，以及重新创建服务后从磁盘恢复备份。读取预览/列表使用读取租约，执行、备份基线收尾和刷新共用整个任务租约与仓库锁；取消或错误后仍刷新可观察状态。原始备份先写入，恢复基线落盘成功后才标为 Ready 并在日志宣称可恢复；恢复要求仓库、分支、HEAD、所选文件指纹及备份摘要一致，保护后来修改。备份及恢复结果通过既有任务历史归档。

2026-10-09 前端 npm ci/build、Go 全量测试（无缓存，180 秒包级超时）、go vet、Windows wails3 build 全部通过。根包选择撤销/恢复和既有确认操作竞态检查通过，相关引擎竞态在引擎提交中通过。绑定由 wails3 生成，未手动编辑。

## P16 真实界面验收

使用端口 9276 的真实 Wails server、隔离 APPDATA 和自行创建的临时仓库。仓库含两个已跟踪修改文件及一个暂存新增文件；chosen.txt 的暂存内容为 staged，工作区为带两个尾空格和 CRLF 的 working。

1. 文件预览只列出 chosen.txt 和 other.txt；默认全不选、备份关闭、确认按钮禁用。只勾选 chosen.txt 和备份，明确确认后执行。
2. 撤销后 chosen.txt 回到原提交；other.txt 的修改和新增文件的暂存内容保持一致，备份文件实际写入磁盘且 Ready 为真。
3. 菜单恢复入口列出时间、单文件范围及备份 ID；选中且勾选确认才可执行。成功后直接读取文件字节为原 working 双空格 CRLF，暂存区为 staged；未选文件和暂存新增文件保留。
4. 日志和持久化任务历史显示撤销与恢复各成功一次，记录可恢复备份 ID。对话框和文件列表可独立滚动；默认 1265×712 浏览器尺寸确认区域完整可见。
